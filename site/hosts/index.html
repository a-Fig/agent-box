Hosts & GPUs

Use a dedicated Linux box around the clock, or share your Windows gaming PC without losing frames or RAM.

Shared Windows PC

On Windows 11 with WSL2, boxtray puts a mode switch in the notification area and syncs with boxd inside WSL.

  • Full — Uncapped: all configured host CPUs (up to 24), 24 GiB RAM, and GPU access.
  • Shared — Background builds live within half the host budget (12 GiB total) so the desktop stays responsive.
  • My PC — Running containers freeze immediately via cgroups, queued runs pause without failing, and cgroup memory.reclaim hands memory back to Windows (about 3.2 s to reclaim and 35 s to settle). Switch back to Shared or Full and paused runs resume in place.

GPU passthrough

Request a GPU box with -s gpu in CLI or size: "gpu" in box_run (4 shared / 6 full CPUs, 8 GiB RAM, 40 GiB disk). On WSL2 hosts, box maps /dev/dxg and /usr/lib/wsl into the container so CUDA and PyTorch use your NVIDIA GPU.

Measured on a shared RTX 3070 host: a 4096×4096 PyTorch matrix multiply finishes in 10 ms on the GPU box vs 590 ms on CPU. Only one GPU job runs at a time, so workloads never contend over VRAM.

Queue when busy

When a host is in My PC, full on memory/CPUs, or already running a GPU job, you can pass queue: true (or set --queue).

boxd stores snapshots in a crash-safe disk queue up to 2 GiB per bundle, schedules fair-share FIFO by agent session, nudges agents after 20 minutes if the host stays busy, and expires unstarted entries after 24 hours. Open box ui to reorder or cancel queued runs.

Dedicated Linux server

A cloud VM or home Linux server runs the same provisioning script without Windows modes or tray switches. Minimums: Ubuntu or Debian, Linux kernel 6.12+, at least 6 GiB RAM (16 GiB+ recommended), and 75 GiB free disk for the container pool and /cache.

sudo bash provision/setup-host.sh --build-base

The provisioning guide covers both Ubuntu/Debian servers and the two-step Windows PC installer, plus exact uninstall commands.
