About agent-box

Run heavy builds, race tests, and GPU workloads on your own server or gaming PC, inside isolated Incus containers.

Why it exists

Run two coding agents side by side on a laptop and wait for go test -race, Gradle, or a full Vite suite: fans pin at full speed, battery drops, and every edit slows to a crawl.

agent-box moves those heavy runs onto a fast machine you already own. Each run executes inside an isolated Incus container with warm caches, and your agent receives the result when it finishes.

How it works

Your agent calls box_run from a repo, or you run box run -- .... box bundles your working tree — tracked edits and untracked files, without committing — into an Incus box on your host. Each repo reuses its box for up to 2 hours idle (unless another waiting launch needs the room), or pass --new for a throwaway box.

Shared caches under /cache keep Go builds and modules, Gradle, npm, and uv warm across runs. The runner walkthrough follows a job from bundle to completion.

What it works with

The box client runs on macOS, Linux, and Windows over the Incus HTTPS API (and tailscale serve on a tailnet), and wires MCP tools into Claude Code, Codex, and Antigravity (plus a snippet for Cursor). In T3 Code, long background runs wake your thread when they finish via box watch, so zero context goes to polling.

box ui and box app open the live web UI to inspect boxes, switch a shared Windows gaming PC between Full, Shared, and My PC modes, and read logs or history.

Who makes it

a-Fig maintains agent-box on GitHub, and contributors submit pull requests.

The source code is at github.com/a-Fig/agent-box.
