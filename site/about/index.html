agent-box

About agent-box

Run heavy builds, race tests, and GPU workloads on your own server or gaming PC, inside isolated Incus containers.

Why it exists

Run two coding agents side by side on a laptop and wait for go test -race, Gradle, or a full Vite suite: fans pin at full speed, battery drops, and every edit slows to a crawl.

agent-box sends those heavy runs to a fast machine you already own. Each run gets an isolated container with warm caches, and your agent receives the result when it finishes.

How it works

Your agent calls box_run from a repo, or you run box run -- .... box snapshots the working tree — tracked edits and untracked files, without committing — into an Incus container on your host.

Shared caches under /cache keep Go modules, Cargo crates, Gradle caches, and Node installs warm between fresh containers. The runner walkthrough follows a job from snapshot to push notification.

What it works with

The box client runs on macOS, Linux, and Windows over Incus TLS or Tailscale SSH, and wires MCP tools into Claude Code, Codex, and Antigravity (plus a snippet for Cursor). In T3 Code, background runs wake your thread with a push message when they finish, so no context window goes to polling.

box ui and box app open the live web UI to inspect boxes, switch a shared Windows gaming PC between Full, Shared, and My PC modes, and read logs or history.

Who makes it

Tyler Darisme makes and maintains agent-box, as a-Fig on GitHub. Others contribute through pull requests.

The source code is at github.com/a-Fig/agent-box.
